# Правила Медики

- 10 ноября 2026 пользователь прямо попросил перенести проверенные действия в приложение. Основной `/` и `/family` теперь рабочий семейный экран; записи сохраняются только по явному действию в существующем журнале. Прежние инструменты доступны через `/manage`. `/design-study/a1` остаётся независимым демо, без клинических запросов.

- Дизайн обсуждается в `/design-study/a1`, а не в рабочем `/family`. Пользователь явно разрешил копию реальных данных для этого демо: приватный `site/data/design-study/a1-family.json`, без Git/внешних сервисов/скриншотов реальных данных. Браузер читает только отдельный снимок, отметки хранятся локально во вкладке. Рабочие ID удалены, доступ к clinical API дополнительно закрыт CSP. Не переносить следующие итерации дизайна в приложение без прямой просьбы. Старый синтетический пример — `/design-study/a1-synthetic`.

- `/family` — рабочий A1 на реальных данных: публична пустая оболочка, назначения/история загружаются защищённым API. Галочка пишет факт только по явному действию пользователя; снятие отменяет запись с сохранением истории. Автоматизированные отметки проверять только во временной синтетической базе. Не встраивать реальную базу в HTML/JS/Git и QA-скриншоты. Не превращать точное время в слот еды из догадки. В раскрытии — структурированное назначение; свойства препарата и исходный текст — в отдельном dialog. Не отключать ранее доступные действия при переносе UI без просьбы пользователя.

- Перед новой компоновкой сверяться с матрицей в `design-study/DESIGN-RULES.md`: для каждого сценария указаны частота, видимые данные и место действия. Статус фазы в обзоре — пассивный текст; смена фазы и распорядок — в лечении человека. История сначала открывает сведения о факте, затем явное исправление. Язык ввода — настройка, а не постоянный сосед голосовой кнопки. Не выводить редкое действие на главный экран только потому, что для него есть API.

- Семейный обзор изначально свёрнут. Не раскрывать первое лекарство автоматически на планшете; основные дозы обоих детей должны быть видны до раскрытия. Дата старого измерения обязательна, часы без даты не должны создавать впечатление свежего факта. Выбор отображаемого слота не меняет назначение и не означает рекомендацию догнать старый приём.

- Мобильный дизайн: фактические зоны действий не меньше 48 × 48 CSS px, свободный промежуток между ними не меньше 8px. Раскрытие лекарства и отметка приёма — раздельные действия с промежутком 12px. Обязательны геометрическая проверка и touch-нажатия на центре/краях зон; скриншот не заменяет их. Полные правила и разобранная ошибка A1 v2: `design-study/DESIGN-RULES.md`.

- Код продукта находится в `site/`. Процесс запускается только через Local Projects Dashboard, сервис `web`. Исходные медицинские документы и `site/data/` не коммитить и не отправлять внешним сервисам.
- Реальные назначения врача не генерировать как демо. Тесты и скриншоты использовать только с синтетическими данными во временной базе. Сервер слушает loopback.
- Дозировка назначения и концентрация препарата — разные поля. OCR создаёт предложения, которые требуют ручной сверки. Часы и длительность не достраивать из догадки.
- Плановые события и фактические записи хранятся отдельно. Изменения схемы не изменяют прошлую дозу или время в журнале.
- Проверка совместимости явно неполная. Новые медицинские правила добавлять только с первичным источником и датой проверки; не выводить общий статус «безопасно».
- Перед длительной работой пройти сквозной canary; до реальных выписок проверить импорт/сохранение/расписание/отметку/перезапуск/копию/восстановление на синтетическом изображении. `reports/canary-result.json` содержит последний результат.
- При изменении распознавания проверять строку с номером пункта, цифровое торговое название, десятичную дозу и отсутствие выдуманных часов. Перед выделением названия удалять только явный маркер списка; число в названии не считать концентрацией без единицы.
- Распознавать многострочные абзацы целиком: сохранять время, дни недели, область дозы «в каждую ноздрю», условную ветку и относительные интервалы. Концентрацию из нескольких компонентов сохранять целиком. Явно неразборчивые названия не предлагать как готовые лекарства.
- Рукописный OCR после установленных ошибок не прогонять повторно ради уверенного результата. Сохранять исходный вывод и оригинал, переходить к ручной сверке; расхождения кратности и доз не разрешать автоматически. Домашние записи не считать фактом приёма по одному времени на доске.
- Возраст со слов пользователя хранить вместе с датой сообщения, без выдуманной даты рождения. Общие бумаги могут принадлежать двум профилям, а назначение и факт каждого ребёнка остаются отдельными.
- Приём по необходимости обязан хранить фактические дату и время в поясе назначения; в UI он не увеличивает число обязательных плановых приёмов. Копия обязана сохранять эти поля.
- Перед сдачей: `npm test` и headless `scripts/canary.mjs`; после изменений интерфейса проверить все варианты на одном тестовом приложении, затем отдельно интеграцию с запущенным сервисом. Playwright для проверок доступен через `PLAYWRIGHT_MODULE` или dev-install.
- Поле «зачем» хранить как введённую пользователем цель из назначения, без вывода диагноза по названию лекарства. Цель в записи фактического приёма — снимок на момент записи; правка будущего назначения не переписывает историю. Отображаемое имя не меняет исходное имя/ID профиля и связи документов.
- Пользовательский адрес локального домена — `http://medika.localhost`, без порта. Внутренний 4382 используется только сервером/readiness. Проверять путь через системный Caddy, сессию и API с внешним Host, сохраняя проверку Origin. До вывода об отсутствии слушателя проверять HTTP и существующий launchd-сервис: lsof без root может не показать его сокеты. Конфигурацию других доменов не перезаписывать.
- Для iPad настроены `http://192.168.0.38` и `http://macbook-air-5.local`, без порта; маршрут Caddy ограничен текущей домашней подсетью, backend остаётся на loopback. `localhost` не является адресом Mac на другом устройстве. Проверку по Wi-Fi IP с Mac не называть проверкой физического iPad. Изменение DHCP-адреса требует сверки Caddy и MEDIKA_LAN_HOSTS.




- Текущая модель: пациент → личная история → событие/лекарство, фактическая доза и время. Предписание врача («Профилактика»/«Острая фаза») — свёрнутый контекст. Прежняя общая доска сохранена в Git, её ограничения размеров/меню больше не применяются.
- Имя — Алиса. Компактная шапка, крупные название/доза/время, подробности раскрываются. Общий ввод: голосовая кнопка без предварительного выбора пациента/клавиатуры. Однозначная фраза с именем создаёт событие после паузы; результат появляется в истории без всплывающего подтверждения. Исправление и отмена — в карточке факта. Неясная фраза требует сверки. Текстовый ввод свёрнут. Фаза 2 — голосовой диалог; не добавлять его заранее.
- Голос: только ru/en, локальный whisper.cpp, не отправлять аудио наружу; временные файлы удалять при успехе и ошибке. Новые факты температуры — activities, старые temperatures сохранять и объединять в ленте. Связь с Rx проверять по пациенту. Копии v4 поддерживают прежние версии и новые метаданные без переписывания фактов.
- Разбор речи не является медицинским источником: диапазон доз не превращать в одно число, концентрацию не считать дозой, несколько событий/отрицания не превращать в положительный приём. Неясное прошлое время просить заполнить. Сохранять исходную фразу; автоматически записывать только однозначное событие с явно названным пациентом. Не подставлять человека из открытой вкладки в общий голосовой ввод. Относительное время отсчитывать от начала записи, не от завершения ASR.
- Для браузерного микрофона на LAN нужен доверенный HTTPS: macbook-air-5.local / 192.168.0.38. CA medika отдельная, публичный сертификат доступен по /medika-ca.cer. Не устанавливать системное доверие автоматически; не объявлять синтетический browser test проверкой физического iPad.
- Внешняя ссылка из чата должна открывать GET / и публичный сертификат: blanket-запрет Sec-Fetch-Site/Origin не применять к этой оболочке. API, изображения документов и любые записи сохраняют проверки; regression-test обязан проверять доступ и запрет вместе. При браузерной проверке включать клик со стороннего origin, а не только page.goto.

- Пользователь явно выбрал существующую подписку Codex и GPT-6.1 Sol для объединения двух расшифровок. Разрешены текущая введённая/распознанная фраза и минимальный словарь имён/ID/названий лекарств. Не передавать фотографии, файлы базы, историю, возраст/диагнозы и полные назначения. Sol получает только текст: локальные Whisper Small и Whisper Medium остаются первым этапом, не объявлять качество ASR исправленным только заменой семантического парсера.
- Terra: отдельный CLI в site/tools/codex, ChatGPT auth без API-ключей, ephemeral JSON Schema, без shell/apps/MCP/multi-agent, один запрос за раз и без автоматических повторов/смены провайдера на лимите. Провал модели не создаёт события. Повтор clientKey возвращает факт без нового модельного запроса. Настоящие AI-canary только с синтетическими данными, последовательно; unit-тесты не расходуют подписку.

- Качество голоса не объявлять проверенным по одной удачной TTS-фразе. Сравнивать одни и те же WAV с именем, температурой/дозой, лекарством и временем; отдельно считать уточнения и неверные автоматические факты. Синтетический голос/шум не считать проверкой реального телефона. Сам факт принятия localAudio протоколом не доказывает, что модель разобрала аудио.

- /voice-lab — отдельная разрешённая пользователем запись и долговременное хранение тестового голоса в site/data/voice-lab. Это исключение из удаления временного аудио основного ввода, но не разрешение включать реальный голос в Git/скриншоты/тестовые отчёты. Тестовая страница не обращается к клиническому store для создания/изменения фактов. Эталоны фраз не передавать моделям.
- Все варианты лаба получают один сохранённый WAV с одинаковым SHA256; для одинакового Whisper переиспользовать расшифровку. Сохранять результаты каждого шага, оценки и время записи; при перезапуске не повторять готовые запросы. Любая ошибка/лимит останавливает очередь. Аудио и результаты защищены сессией/Origin; для Safari поддерживать Range. /voice-lab как публичная оболочка разрешает переход из чата, её API остаётся защищённым.

- Whisper Base запрещён и технически удалён из рабочих моделей: основной ввод Whisper Small + Whisper Medium последовательно на одной записи. Не возвращать Whisper Base в установщик, API, варианты/дефолты тестовой страницы или исполняемые benchmark-скрипты. Исторические результаты и сохранённый JSON не удалять/не переименовывать в результаты новой модели. Миграция выбора браузера меняет только выбранный вариант, не результаты.

- По требованию пользователя разрешено восстанавливать названия препаратов после ASR по фонетике и контексту: приоритет списку пациента, затем общему словарю/известным реальным названиям. Убедительное исправление само по себе не требует уточнения. Не подменять явно названный другой препарат ближайшим из списка; несколько правдоподобных кандидатов требуют уточнения. Числа/дозу не выводить из назначения. Lab использует только минимальные имена/названия, эталоны не передавать; при смене правил/словаря пересчитывать только семантику, сохраняя старый результат/оценку в resultHistory.

- Фото упаковок: локальные JPEG ≤320 px и ≤32 КБ каждый, один-два на название. Справочное фото выбирается только по точному известному имени/алиасу, не по фонетике; неизвестные препараты не подменять похожей упаковкой. Свои фото защищены API-сессией, общие для одного названия и включены в backup v4. Публичные справочные фото и ссылки на источники хранятся в репозитории; инструкции/дозы с сайтов не импортируются. Различие дозировки на фото Nasacort явно подписано, назначение не менять. Не добавлять фото реальных пользовательских упаковок в тесты/Git.

- Для узнавания препарата без коробки основной снимок в превью — сам флакон, тюбик, ампула или блистер. Пара фото: сначала упаковка, затем препарат. Единственный собственный снимок трактуется как фото препарата. Справочные фото можно кадрировать только отображением реального снимка, без генерации этикеток/упаковок; источник сохранять.

- Ошибки ASR в именах разрешено восстанавливать моделью по people (например, «да нет»/«Доня» → Даня в подходящей фразе), с дословным personMention из источника. Не возвращать обязательное буквальное совпадение для такого восстановления. Явное другое имя, неизвестный ID, отсутствие исходного фрагмента и несколько названных людей остаются ограничениями. Не подставлять человека из открытой вкладки/истории/дозы. При изменении правил обновлять parserRevision, сохраняя прежние результаты lab.

- Объединённый голосовой путь: обе исходные расшифровки с заголовками → один Sol (low) с минимальным контекстом имён и лекарств. Сохранять обе версии в sourceText. Не усреднять противоречащие дозы/температуры; неоднозначность передавать на уточнение. ASR-замок удерживать на оба прохода; частичный успех не выдавать за полный. Lab переиспользует отдельные ASR-кэши, сохраняет каждый до следующего этапа и не повторяет завершённые шаги при возобновлении.

- Рабочая диктовка `/family`: запись микрофона не блокируется ASR/разбором предыдущих событий. Очередь в `voice-queue.js` хранит только незавершённые задания в IndexedDB текущего origin (10 × 8 МиБ); ru/en, recordedAt и clientKey фиксируются на каждую запись. ASR/модель — последовательно; audio удаляется после расшифровки или ошибки. Ошибка/429 и прерванная обработка требуют явного решения, без автоматического повтора. При повторе сохранения использовать прежний текст и ключ; не создавать дубль после потерянного ответа. Неясный результат показывать через условный вход «Разобрать», не открывать окно поверх следующей диктовки. Фоновый результат не меняет выбранного человека и не обновляет редактируемый профиль под открытой формой. Проверять реальные capture/encoding с синтетическим микрофоном, задержку обоих этапов, порядок, время от начала записи, перезагрузку и потерянный ответ в `site/scripts/voice-queue-canary.mjs`; не объявлять это проверкой реального голоса/iPad.

- Успешное распознавание голосового события молча обновляет журнал: не показывать toast/плашку «Событие записано» и кнопку отмены поверх экрана. Исправление и отмена доступны в карточке события истории. Неясность остаётся в очереди «Разобрать»; ошибки не считать успешной записью. Регрессия проверяется наблюдением за уведомлениями во время завершения очереди.
