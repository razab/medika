# Правила Медики

- Код продукта находится в `site/`. Процесс запускается только через Local Projects Dashboard, сервис `web`. Исходные медицинские документы и `site/data/` не коммитить и не отправлять внешним сервисам.
- Реальные назначения врача не генерировать как демо. Тесты и скриншоты использовать только с синтетическими данными во временной базе. Сервер слушает loopback.
- Дозировка назначения и концентрация препарата — разные поля. OCR создаёт предложения, которые требуют ручной сверки. Часы и длительность не достраивать из догадки.
- Плановые события и фактические записи хранятся отдельно. Изменения схемы не изменяют прошлую дозу или время в журнале.
- Проверка совместимости явно неполная. Новые медицинские правила добавлять только с первичным источником и датой проверки; не выводить общий статус «безопасно».
- Перед длительной работой пройти сквозной canary; до реальных выписок проверить импорт/сохранение/расписание/отметку/перезапуск/копию/восстановление на синтетическом изображении. `reports/canary-result.json` содержит последний результат.
- При изменении распознавания проверять строку с номером пункта, цифровое торговое название, десятичную дозу и отсутствие выдуманных часов. Перед выделением названия удалять только явный маркер списка; число в названии не считать концентрацией без единицы.
- Распознавать многострочные абзацы целиком: сохранять время, дни недели, область дозы «в каждую ноздрю», условную ветку и относительные интервалы. Концентрацию из нескольких компонентов сохранять целиком. Явно неразборчивые названия не предлагать как готовые лекарства.
- Рукописный OCR после установленных ошибок не прогонять повторно ради уверенного результата. Сохранять исходный вывод и оригинал, переходить к ручной сверке; расхождения кратности и доз не разрешать автоматически. Домашние записи не считать фактом приёма по одному времени на доске.
- Возраст со слов пользователя хранить вместе с датой сообщения, без выдуманной даты рождения. Общие бумаги могут принадлежать двум профилям, а назначение и факт каждого ребёнка остаются отдельными.
- Приём по необходимости обязан хранить фактические дату и время в поясе назначения; в UI он не увеличивает число обязательных плановых приёмов. Копия обязана сохранять эти поля.
- Перед сдачей: `npm test` и headless `scripts/canary.mjs`; после изменений интерфейса проверить все варианты на одном тестовом приложении, затем отдельно интеграцию с запущенным сервисом. Playwright для проверок доступен через `PLAYWRIGHT_MODULE` или dev-install.
