# Медика

## Назначение

Отдельное локальное приложение для нескольких людей: назначения врача, расписание и журнал фактического приёма, распознавание выписок и справочные предупреждения. Первая версия 0.1.0 запущена 8 ноября 2026 года. Основание: [первичная концепция](../../user-suggested/20-family-medication-monitor.md). Текущие возможности и ограничения: [STATUS.md](STATUS.md).

## Как использовать

На Mac: http://medika.localhost. Для iPad/телефона в той же домашней сети: http://192.168.0.38 или http://macbook-air-5.local, без порта. DNS менять не требуется: второе имя — существующее Bonjour-имя Mac. Проверка с самого Mac прошла для обоих адресов; физический iPad не проверен. Mac должен работать, а роутер не должен изолировать клиентов Wi-Fi. При изменении DHCP-адреса нужно обновить IP в Caddy и MEDIKA_LAN_HOSTS; Bonjour-имя обычно продолжит работать в той же подсети.

Главная начинается с лекарств. Подтверждённые приёмы показаны по времени для всей семьи; ниже — ещё не подтверждённые назначения из выписок в таблице «когда / препарат и доза / кому / срок». При отсутствии подтверждённого плана сразу видна эта таблица. Одинаковые строки общей бумаги объединены визуально, а настройка схемы остаётся отдельной для каждого человека. Условная схема при симптомах вынесена отдельно. Меню свёрнуто, все четыре участника видны в компактной строке; пустые профили не вытесняют лекарства с первого экрана.

Отметка приёма, редактирование, сверка и оригинал открываются поверх доски. После возврата из фильтра одного человека главная всегда показывает всех. Участники: папа, мама и два детских профиля; имя «Лиса» на доске связано с исходным профилем Алисы и тем же ID. Текущие курсы сохраняют дозу, цель «зачем», условия, срок и день курса.

Цель назначения вводится отдельным полем и сохраняется в расписании/истории/копии; отсутствующая цель явно обозначается. Она не выводится автоматически из бренда препарата. Черновики показывают известные часы и дозы, недостающие сведения и источник в общей таблице; сами по себе они не создают действующее расписание. Для подтверждённой схемы цель видна рядом с приёмом, для черновика — в исходной формулировке. Кнопка с именем ребёнка открывает его назначение с заполненными данными из бумаги и пустой неподтверждённой датой начала.

В разделе «Выписки» можно исправить распознанный текст и заполнить назначение из выбранной строки. Поддерживаются PNG, JPEG и WebP до 12 МБ / 40 мегапикселей. Неясная дозировка не активируется без ручного заполнения. Фиксированные часы и точные интервалы задаются отдельно. Уведомления доставляются только при открытой вкладке и разрешении браузера.

При исправлении отметки прежняя запись остаётся в истории. В «Данные и настройки» доступны резервная копия и восстановление; копия включает оригиналы изображений. Конфликт версий при восстановлении отклоняет операцию целиком. В рабочей базе четыре семейных профиля, в каждом детском сохранены три фотографии; тестовые записи в неё не переносились. Материалы остаются черновиками до сверки назначений. Прямая ссылка на оригиналы: http://medika.localhost/#documents.

Дни недели выбираются отдельно от часов. Для назального препарата область «в каждую ноздрю» сохраняется в назначении, расписании, журнале и копии. Помощник длительности показывает календарное окончание; его границу нужно сверить с назначением. Возраст без даты рождения хранится как возраст на определённую дату. В выписках отдельно сохраняются текст для сверки, исходный OCR, источник «врач/семья» и заметки с неоднозначностями. Домашняя доска не создаёт автоматически назначения или фактические приёмы.

## Архитектура

Код — `site/`. Node.js 24+ с встроенной SQLite, браузерный интерфейс без runtime npm-зависимостей. Распознавание изображений — отдельная локальная CLI на Swift с Apple Vision. Проверка взаимодействий — ограниченные явно перечисленные правила со ссылками на источники; полноценная медицинская база не подключена.

## Данные и связи

`site/data/medika.sqlite` и `site/data/uploads/` содержат медицинские данные и исключены из Git. Backend слушает только 127.0.0.1; Caddy открывает отдельный маршрут для домашней подсети 192.168.0.0/24. Удалённых сервисов распознавания и аналитики нет. Режим рассчитан на доверенные устройства домашней сети: отдельные аккаунты и TLS не настроены. Доступ из интернета не настраивался. Резервная копия должна храниться пользователем как медицинские данные.

## Запуск и остановка

Через Local Projects Dashboard, сервис `web`; профиль HTTP readiness проверяет `/api/health`. Не запускать второй экземпляр вручную. macOS OCR предварительно компилируется командой `npm run ocr:build` из `site/`.

Профиль проекта: `5bc913d8-ae85-470b-a91e-251a2a589364`, конфигурация для воспроизведения — `project.toml`. При передаче runtime `running`, health HTTP 200, watch включён для `site/public`, `site/lib`, `site/server.mjs`. Фактическое подтверждение — `reports/live-service.json`; проверки — `reports/test-report.md`.

Существующий системный Caddy (`homebrew.mxcl.caddy`) принимает HTTP на 80 и проксирует маршруты на внутренний loopback-порт 4382. Конфигурация — `infra/medika.caddy`, она добавлена в `/opt/homebrew/etc/Caddyfile`; прежние маршруты сохранены. `medika.localhost` ограничен самим Mac; IP и Bonjour-маршрут разрешены только loopback и домашней подсети. Backend принимает эти два дополнительных имени через `MEDIKA_LAN_HOSTS`, сохраняя проверку Origin. Автозапуск самого проекта при входе в систему не настроен. Подтверждение LAN-пути: `reports/lan-access.json`; причина прежней ошибки и границы проверки: `reports/ipad-lan.md`.
