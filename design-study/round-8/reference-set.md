# Медика — разнообразие структуры, серия 8

20 ноября 2026. Пользователь оставил серию 7 запасной и прямо потребовал пять новых вариантов с иной структурой и разным отображением остатка курса. Стандартные три варианта скилла заменены явно запрошенными пятью. Рабочий интерфейс не меняется.

## Фактическая ошибка подхода и защита

Обзор серии 7 просмотрен: во всех пяти почти одинаковый каркас — человек → две строки → доза/точки/галочка справа. Предыдущий общий промпт буквально фиксировал этот LAYOUT и semantic order, поэтому отдельные палитры не могли дать структурного разнообразия. Проблемная часть остановлена. Теперь общий контракт задаёт смысл/значения, но НЕ геометрию и НЕ единый порядок. Каждое направление имеет свой `structure`, `coursePresentation`, `displayOrder`; для сортировок по состоянию/курсу человек подписывается у каждого лекарства. Старые картинки не передаются как положительный визуальный якорь.

## Опоры и fingerprint

RF1 Things, RF2 Bear iPhone, RF3 Bear iPad — наблюдаемые native/platform поверхности из [серии 6](../round-6/reference-set.md), их URLs/осмотр и кеш сохраняются. Берём первичность задачи/читаемость и понятные действия, не копируем брендинг/синие даты. R7-negative — [показанный обзор серии 7](../../site/public/design-study/round-7/overview.png), повторно просмотрен в этом проходе: одинаковый силуэт служит анти-референсом. UF-core — локальный сценарий найти человека/препарат → отметить факт → увидеть состояние/остаток; четыре синтетических строки из shared-data.json. Три из пяти опор — реальные native/platform поверхности. Общая палитра светлая с умеренным фиолетовым, чтобы структура не подменялась сменой цвета.

## Пять проверяемых различий

S1: две пары плиток по людям, остаток как отдельная календарная страница.
S2: вертикальная ось слотов и четыре именованных остановки, остаток на крайних лентах.
S3: билеты действий с крупной дозой слева, остаток на уголке, кнопка с текстом.
S4: плоский чек-лист по состоянию отметки, доза под именем, курс словами, без картинок/карточек.
S5 (после сравнения): доска остатка курса 1+3 — широкий последний день и три вертикальные полосы с числами дней; сортировка явно подписана.

Проверка силуэта: если два рендера снова дают тот же стандартный список с дозой справа, слабый вариант не принимается и меняется только его архитектура. Число оставшихся дней не превращается в процент/прогресс курса: общий срок/начало/конец неизвестны. Календарные прямоугольники курса не заменяют круглые точки приёмов. Крупные действия/свободные промежутки обязательны при рабочей реализации; растр их не доказывает. Сначала S1 проходит путь генерация → сохранённый PNG/хеш → HTTP → крупное открытие/обновление → вход/изоляция, затем остальные четыре. Общий набор экранов/дизайн-система не создаётся до выбора; visualLock.status=unlocked.

## Правка после сравнения силуэтов

Первый S5 корректен по данным, но четыре горизонтальные полосы с числом слева слишком похожи на S3 с дозой слева. Он отвергнут для итоговой пятёрки. Изменение подхода локально: S5 становится доской 1+3 — широкий последний день сверху и три вертикальных курса под ним, одновременно видимых. Остальные четыре структуры не меняются. Приёмка проверяет и новый силуэт, и неизменность всех четырёх строк/точек/доз.
