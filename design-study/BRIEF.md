# Медика: сравнение инструкций по дизайну

## Выбранное направление: A1, вторая редакция

По обратной связи пользователя: только светлая тема; A1 основной, A2 запасной, A3 исключён из активной галереи. Сохраняются фильтры «Все / Алиса / Даня / Мама / Папа», цвет людей в общем обзоре и фаза у каждого ребёнка. Не показывать дату, «Сегодня» и часы плановых слотов. Показывать названия еды, а интервалы — только у зависимых лекарств. Часы фактической истории сохраняются.

Один и тот же A1-компонент: на телефоне карточки друг под другом, на iPad от 700px две колонки; галерея проверяет мобильный компонент по ширине его контейнера. На человека несколько препаратов: у Алисы два в текущем слоте и один в следующем, у Дани три и один. Название и доза находятся на одной строке, шрифт 15/16px. «1 пшик / 2 пшика» — короткая подпись; полный исходный текст со значением «в каждую ноздрю» остаётся в раскрытии, не теряется. Названия, дозы, инструкции и зависимость — синтетические, не из врачебных документов.

Структура: `[фильтры] → Ужин → [Алиса: лекарства / Второй ужин] [Даня: лекарства / Второй ужин] → последние события → голос`. На iPad карточки имеют общую верхнюю линию и выровненный следующий слот. Палитра A1 сохраняется: paper #FDFEFE, ink #172337, blue #315AC1, person-blue #F1F5FC, person-sand #FAF2E8. Имя и фаза компактные; цвет обозначает человека, не клиническую оценку.

В A1 нативные radio-фильтры и details позволяют проверить выбор человека и подробности без JavaScript/API. Голос и отметки остаются элементами макета. Данные не сохраняются и не создают фактов лечения. Рабочий интерфейс приложения не заменяется.

Запрос 2026-11-09: найти дизайн-скиллы, применить каждый к 2–3 простым статичным дизайнам. Производственный UI не заменяется. Эксперимент ограничен тремя выбранными скиллами, девятью макетами одного дня, без клинических API и интерактивности внутри макетов.

Пользователь: взрослый, который одной рукой ведёт семейные лекарства на телефоне/iPad. Первое решение: кому сейчас дать что и сколько. Следом: следующий слот и что уже произошло. Первый экран не рекламирует приложение. Разные фазы относятся к отдельным людям. Отсутствие назначений у родителей не занимает карточек.

## Воспроизводимость

- Прочитанные исходные SKILL.md, лицензии и точные SHA: `references/`.
- Генератор с общим синтетическим набором: `site/design-study/build.mjs`.
- Сборка: `node site/design-study/build.mjs`. Результат — статичные HTML, никаких чтений базы.
- Страница сравнения всех вариантов: `/design-study`. Отдельные экраны: `/design-study/a1` … `/design-study/c3`.
- Сохраняются только вымышленные названия препаратов и дозы; это не назначения и не медицинские рекомендации. Фотографии, записи и данные пользователя не используются.
- Все экраны делает один агент с разными инструкциями. Это исследование направлений, а не контролируемый рейтинг качества самих скиллов.

## Выбор скиллов

1. Anthropic Frontend Design: визуальная идентичность, осмысленные структурные элементы, одна выразительная идея. Применяется только к A1–A3.
2. UI/UX Pro Max: приоритеты доступности, контраста, типографики и плотности, локальная поисковая база. Применяется только к B1–B3. Первый `--design-system` запрос `healthcare medication mobile dashboard` выдал маркетинговый hero/testimonials и неуморфизм. Один повтор `internal task dashboard` снова дал маркетинговый pattern, поэтому этот pattern не применён. Сохранены подходящие Flat Design / плотность 9 и Fira Sans; отдельный style-поиск `dashboard dense minimal` дал релевантный Minimalism & Swiss Style. Рабочую структуру приложения определяет бриф, не маркетинговые рекомендации. Шрифт Fira Code для заголовков заменён системным sans для бытового чтения; это явное отклонение от рекомендации, а не результат поиска. В макетах используется локальный Golos с кириллицей: буквальный рекомендованный шрифт не является условием скилла.
3. ibelick Baseline UI: табличные цифры, выверенный ритм, один акцент, без градиентов, движения и glow. Применяется только к C1–C3. Существующий проект использует собственные CSS-токены и vanilla HTML; поэтому сохраняются CSS-токены, не добавляются Tailwind/React/cn. Интерактивных примитивов в макетах нет; навигация галереи — обычные ссылки.

Отсмотрены, но не применены: текущий Taste Skill 2.5.1 ориентирован на промосайты (hero на экран, анимационные moments), что противоречит задаче; Impeccable 4.8.1 требует отдельного процесса контекста/согласования направления/построения, избыточного для этой ограниченной сравнительной пробы. Не выдавать эти скиллы за протестированные.

В A2 поле дозы имело max-width 90px, а слово «впрыскивание» в выбранном Manrope занимает 100px. Одного breakpoint было недостаточно: ограничение влияло и на 390px. Проверка далее запрещает обрезание названий и доз.

## A1 на сохранённых данных — `/family`

Отдельная оболочка, не замена основного журнала. Настоящие назначения, дозы, фазы и история приходят из существующих защищённых API; в Git и статические ресурсы медицинские значения не подставляются. Предпросмотр только читает, не создаёт клинических фактов. Общий со статичным A1 модуль `family-card.js` сохраняет правила 48px / 8–12px и раскрытие исходной инструкции. Подтверждённые курсы отбираются по периоду/фазе/пациенту; прошлые записи не пересчитываются по изменённому назначению. Непривязанный приём не превращается в еду. Точные часы отдельного назначения скрыты из краткого списка, сохранены в инструкции; явный интервал виден у связанного лекарства.

Проверка на реальном API показала необходимость нескольких строк и в последующем, и в предыдущем слоте: между ними также добавлены 8px. При измерении закрытых вложенных details учитываются только реально видимые summary, а не скрытые потомки, которым Chromium оставляет layout-rect. Полная проверка охватывает раскрытые предыдущие слоты. Синтетические изображения и данные размещаются только во временной тестовой базе. Подключение к реальной базе проверено без скриншотов и без POST/PUT/DELETE; состояние клинических коллекций до/после совпало. Приватный отчёт хранится в site/data.

## Назначение, информация о препарате и рабочие отметки

Пользователь указал на два ошибочных переноса: раскрытие собирало все исходные поля в один текст, а существующие действия отметки были отключены ради «просмотра». Исправлено на общей строке A1: структурированный список назначения отдельно; форма/концентрация/путь отдельно в dialog; условия врача отдельным разделом; сырой исходник свёрнут. Не добавляется медицинская информация из догадок или нового распознавания.

Чекбокс `/family` подключён к общему журналу: запись, сохранение после reload, отмена без удаления истории. Исходные назначения не меняются. Проверяется версия Rx, поэтому изменившийся план требует обновления, а не молчаливой записи новой дозы. Ошибка/потеря ответа приводит к чтению факта из журнала, не к повторному POST. Автоматизированные записи/отмены выполнялись только в синтетической временной базе; настоящий экран проверялся GET-запросами, открытием/закрытием информации и проверкой доступности чекбоксов.

Минимальный сквозной сценарий прошёл перед проверкой всех размеров. Полный `family-preview-canary` проверяет точного человека/дозу, reload, void с сохранением записи, 503, ответ потерян после commit, два быстрых change, отсутствие дублей и неизменность назначений. Проверены 320/390/768/820/1024, раскрытое назначение, modal, закрытие и 48px / 8px зоны. Время браузера в тесте заморожено на начале сценария, чтобы смена календарного дня не делала тест случайным. Снимки открытых состояний снимаются после окончания временной подсветки касания. Все 54 unit/API-теста, общий canary и исходная галерея A1 прошли.

## Исправление границ демо: копия данных и две панели

Запрос пользователя относился к подстановке реальных данных в обсуждаемый макет. Создание `/family`, связанного с рабочим журналом, ошибочно расширило задачу. Дальнейший перенос дизайна в рабочий интерфейс остановлен. Новая реализация находится в исходном стенде `/design-study/a1`; `/family` и основной экран этой правкой не меняются. Для следующих итераций зафиксировано локальное ограничение в AGENTS.md: дизайн проверяется на копии, рабочие действия подключаются только по явному запросу.

По явному разрешению пользователя сделан приватный JSON-снимок в `site/data/design-study/a1-family.json`, без Git и скриншотов реальных значений. Для осмысленной истории выбран последний заполненный день; дата копии показана вне макета. Рабочие идентификаторы удалены из проекции. Отметки и история демо живут в sessionStorage, переживают reload и сбрасываются отдельно. Браузер читает только снимок и сессию; CSP дополнительно блокирует клинические адреса. На планшете слева лекарства и раскрытое конкретное назначение, справа история. На телефоне панели идут последовательно. Прежний синтетический A1 сохранён по `/design-study/a1-synthetic`, генератор его не смешивает с копией.

До полной проверки пройден малый сквозной canary: копия → локальная отметка → reload → отмена → сброс → фильтр → неизменная временная рабочая база. Затем проверены 320/390/768/820/1024px, зоны 48×48 и промежутки 8px, раскрытие, попап и две планшетные ориентации. Синтетический пробный POST заблокирован CSP до сервера. Полный отчёт — `reports/design-sandbox-canary.json`; скриншоты только синтетические. Настоящая копия проверена без снимков экрана: локальная отметка сохраняется после reload и сбрасывается, клинические коллекции и JSON не изменяются, клинических запросов из демо нет. Приватное подтверждение — `site/data/design-study/a1-isolation-check.json`.

При одновременном запуске unit-тестов и нового canary обнаружено совпадение порта 14396 с medicine-photos.test.mjs; один тест завершился внутренней ошибкой Node.js. Точная причина нативного сбоя не установлена. Повторять параллельный запуск с общим портом прекращено; новый canary перенесён на проверенный свободный 14406. Изолированный medicine-photos прошёл, затем полный набор прошёл последовательно: 55/55. Полный клинический canary и синтетическая галерея также прошли. Физические устройства и Safari не проверялись.

## Действия по сценариям на копии данных

В A1 добавлены локальный журнал действий с отменой, приём сейчас/задним числом/с неизвестным временем, общие события для любого профиля, редактирование будущего назначения без изменения фактов, две фазы, личные слоты и переключение типа дня. Копия v2 сохраняет будущие планы и другие фазы, явную связь двух Rx с диапазоном, тип/дату истории и лекарства предыдущих дней. Недостающий набор объясняется, не генерируется. Проверяется согласованность длительности текста и дат; правки курса выполняет пользователь в копии.

Минимальный canary проверяет цепочку действий и сохранение/сброс до матрицы экранов. Обнаруженная ошибка перерисовки закрывала родительский раздел прошлого слота после раскрытия лекарства. Исправлено сохранением раскрытия по человеку; сценарий записи прошлого завтрака входит в canary. Проверка пустого времени выявила неоднозначный Date.parse; теперь формат и календарная дата валидируются до перевода часового пояса. Синтетический пример имеет те же индексы повторов, что рабочий scheduler: иначе проверка не замечала отсутствие автоматического раскрытия на планшете.

59 unit/API-тестов, общий canary и проверка A1 на 320/390/768/820/1024px. Новые кнопки/поля измеряются; касания центра и краёв раскрытия, отметки и фаз проверяются отдельно, формы — на переполнение и разделение зон. Снимки только синтетические. Настоящая LAN-страница проверяется без скриншотов и клинических записей; защищённая CSP по-прежнему допускает только чтение сессии и копии. Реальный голос, физический iPad и клиническая корректность источников не проверялись.

Проверка быстрых касаний центра/краёв также обнаружила потерю DOM-узла из-за полной перерисовки при native toggle. Подход изменён: раскрытие сохраняет левый список на месте и обновляет только правую историю; полный touch-canary после изменения прошёл. Геометрия модального ввода проверяется и с явными полями даты/времени.

Поля native date/time при 390px сохраняли внутреннюю минимальную ширину и сокращали промежуток до 4px, хотя сетка задавала 12px. Явный min-width:0 у полей устранил расхождение; повторная матрица форм на всех пяти ширинах прошла с зонами от 48px и промежутками от 8px.

## Перенос проверенных действий в приложение по прямой просьбе пользователя

10 ноября пользователь явно разрешил рабочую интеграцию. Главный адрес и /family открывают семейный экран с существующими versioned API записи и отмены; /manage сохраняет прежние инструменты врача, фотографий, пациентов и копий. Общая проекция данных имеет отдельный режим удаления идентификаторов для демо; его CSP и отсутствие клинических запросов сохраняются. Свободный голос использует прежнюю цепочку ASR/парсера; запись не берёт человека из активного фильтра.

Новый маршрут исправления факта сохраняет аудит и проверяет версию, не переписывает Rx. Явно неизвестное время поддерживается в API, отображении и backup v4 без выдуманных часов; интервалы не вычисляются от такого факта. При ограничениях времени/числа приёмов возвращается сообщение о неполной проверке. Пользовательские привязки разных личных приёмов должны быть различными; фиксированные привязки самих назначений этим правилом не переопределяются.

Минимальный canary рабочего пути прошёл до расширения: текущая отметка → сохранение → reload → отмена, 503, потерянный ответ и двойной тап. Далее отдельный рабочий сценарий покрывает исправление, версию, фазу, слоты, события пустого профиля, неизвестное время, голосовой маршрут с подменённой ASR и реальным record API, перезапуск. Проверка интерфейса выявила перекрытие кнопки голоса уведомлением и наложение закреплённой панели на список в альбомной ориентации. Исправлено: уведомление выше панели, список имеет собственную область прокрутки, панель занимает отдельное место. Геометрия учитывает реальное отсечение прокруткой; касания прокручивают контроль в видимую область и проверяют центр/края. Автораскрытие выполняется только при первоначальной загрузке, галочка не раскрывает закрытую инструкцию.

Отдельно исправлено отображение фактической дозы: краткая строка получает только число/единицу из факта, без дублирующего «принято» из текста истории. Длинное имя не выходит в соседнюю колонку. Подтверждение голоса очищается перед новым запросом, чтобы старая надпись не считалась результатом следующего действия в тесте. Старый UI-canary адаптирован к изначально раскрытому планшетному назначению.

После перехода проверен настоящий главный адрес по LAN на пяти размерах и HTTPS через существующий локальный CA. Выполнялись только GET и раскрытие/фильтры, без клинических записей и реальных скриншотов. Состав медицинских коллекций совпал и до/после просмотра, и с приватной копией перед переносом. Небольшое фото препарата восстановлено у названия, крупная пара и источник — в отдельной информации. В UI-canary фото синтетическое и сохраняется существующим API.

Дополнительная граница данных: для планового факта с неизвестным временем сохраняется именно введённая известная дата, а не текущий день плана. Это проверено через экран и реальный API временной базы.

Изменения: первоначально закрытые инструкции, одно раскрытие дополнительных слотов и будущих назначений, без дублирующей кнопки на планшете; компактные отступы при сохранении зон 48×48 и промежутков 8px. Старое измерение подписывается датой, история группируется по дням.

Основной слот обзора выбирается как ближайший по явно настроенным часам, без изменения плана. ## Пересмотр иерархии рабочего приложения, 10 ноября 2026

Две большие кнопки фазы в каждой карточке приравнивали редкую смену лечения к ежедневной отметке приёма. Причина — проверяли размеры касаний и наличие функций, но не определили для каждого сценария частоту и уровень информации. Одного уменьшения кнопок было бы недостаточно.

Перед следующей компоновкой использовать матрицу 22 сценариев и поверхностей из `DESIGN-RULES.md`: что видно в обзоре, что читается в раскрытии, где начинается редактирование. Частота — оценка из требований пользователя, не телеметрия. Проверка применяется к реальному приложению `/`, а историческое демо остаётся отдельным стендом.

Исправленный путь: в шапке человека пассивная фаза; смена и личные слоты — «Ещё → Лечение → человек». Строка истории открывает сведения о факте и только затем явную коррекцию. Язык диктовки — в настройках голосового ввода; голос, ручная запись, отметка и короткая отмена после действия остаются рядом с повседневной работой. Важное расхождение курса не скрывается из-за редкости.

Минимальная проверка до полной матрицы: открыть настройки, просмотреть другую фазу, закрыть — база неизменна; сохранить фазу — меняется только выбранный профиль; факты прежние; чтение события не открывает поля; редактирование доступно явно. Затем проверять настоящие компоненты обзора и диалогов на телефоне и планшете, включая центр/края целей, 48×48 и 8 px.
