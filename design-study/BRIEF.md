# Медика: сравнение инструкций по дизайну

## Выбранное направление: A1, вторая редакция

По обратной связи пользователя: только светлая тема; A1 основной, A2 запасной, A3 исключён из активной галереи. Сохраняются фильтры «Все / Алиса / Даня / Мама / Папа», цвет людей в общем обзоре и фаза у каждого ребёнка. Не показывать дату, «Сегодня» и часы плановых слотов. Показывать названия еды, а интервалы — только у зависимых лекарств. Часы фактической истории сохраняются.

Один и тот же A1-компонент: на телефоне карточки друг под другом, на iPad от 700px две колонки; галерея проверяет мобильный компонент по ширине его контейнера. На человека несколько препаратов: у Алисы два в текущем слоте и один в следующем, у Дани три и один. Название и доза находятся на одной строке, шрифт 15/16px. «1 пшик / 2 пшика» — короткая подпись; полный исходный текст со значением «в каждую ноздрю» остаётся в раскрытии, не теряется. Названия, дозы, инструкции и зависимость — синтетические, не из врачебных документов.

Структура: `[фильтры] → Ужин → [Алиса: лекарства / Второй ужин] [Даня: лекарства / Второй ужин] → последние события → голос`. На iPad карточки имеют общую верхнюю линию и выровненный следующий слот. Палитра A1 сохраняется: paper #FDFEFE, ink #172337, blue #315AC1, person-blue #F1F5FC, person-sand #FAF2E8. Имя и фаза компактные; цвет обозначает человека, не клиническую оценку.

В A1 нативные radio-фильтры и details позволяют проверить выбор человека и подробности без JavaScript/API. Голос и отметки остаются элементами макета. Данные не сохраняются и не создают фактов лечения. Рабочий интерфейс приложения не заменяется.

Запрос 2026-11-09: найти дизайн-скиллы, применить каждый к 2–3 простым статичным дизайнам. Производственный UI не заменяется. Эксперимент ограничен тремя выбранными скиллами, девятью макетами одного дня, без клинических API и интерактивности внутри макетов.

Пользователь: взрослый, который одной рукой ведёт семейные лекарства на телефоне/iPad. Первое решение: кому сейчас дать что и сколько. Следом: следующий слот и что уже произошло. Первый экран не рекламирует приложение. Разные фазы относятся к отдельным людям. Отсутствие назначений у родителей не занимает карточек.

## Воспроизводимость

- Прочитанные исходные SKILL.md, лицензии и точные SHA: `references/`.
- Генератор с общим синтетическим набором: `site/design-study/build.mjs`.
- Сборка: `node site/design-study/build.mjs`. Результат — статичные HTML, никаких чтений базы.
- Страница сравнения всех вариантов: `/design-study`. Отдельные экраны: `/design-study/a1` … `/design-study/c3`.
- Сохраняются только вымышленные названия препаратов и дозы; это не назначения и не медицинские рекомендации. Фотографии, записи и данные пользователя не используются.
- Все экраны делает один агент с разными инструкциями. Это исследование направлений, а не контролируемый рейтинг качества самих скиллов.

## Выбор скиллов

1. Anthropic Frontend Design: визуальная идентичность, осмысленные структурные элементы, одна выразительная идея. Применяется только к A1–A3.
2. UI/UX Pro Max: приоритеты доступности, контраста, типографики и плотности, локальная поисковая база. Применяется только к B1–B3. Первый `--design-system` запрос `healthcare medication mobile dashboard` выдал маркетинговый hero/testimonials и неуморфизм. Один повтор `internal task dashboard` снова дал маркетинговый pattern, поэтому этот pattern не применён. Сохранены подходящие Flat Design / плотность 9 и Fira Sans; отдельный style-поиск `dashboard dense minimal` дал релевантный Minimalism & Swiss Style. Рабочую структуру приложения определяет бриф, не маркетинговые рекомендации. Шрифт Fira Code для заголовков заменён системным sans для бытового чтения; это явное отклонение от рекомендации, а не результат поиска. В макетах используется локальный Golos с кириллицей: буквальный рекомендованный шрифт не является условием скилла.
3. ibelick Baseline UI: табличные цифры, выверенный ритм, один акцент, без градиентов, движения и glow. Применяется только к C1–C3. Существующий проект использует собственные CSS-токены и vanilla HTML; поэтому сохраняются CSS-токены, не добавляются Tailwind/React/cn. Интерактивных примитивов в макетах нет; навигация галереи — обычные ссылки.

Отсмотрены, но не применены: текущий Taste Skill 2.5.1 ориентирован на промосайты (hero на экран, анимационные moments), что противоречит задаче; Impeccable 4.8.1 требует отдельного процесса контекста/согласования направления/построения, избыточного для этой ограниченной сравнительной пробы. Не выдавать эти скиллы за протестированные.

## Найденное при визуальной проверке

В A2 поле дозы имело max-width 90px, а слово «впрыскивание» в выбранном Manrope занимает 100px. Одного breakpoint было недостаточно: ограничение влияло и на 390px. Измерены реальные clientWidth/scrollWidth на всех девяти вариантах при 320/390. Исправление: 110px для правой колонки, при узком контейнере доза переходит под лекарство; container query учитывает и уменьшенный макет внутри планшетной галереи. Проверка далее запрещает обрезание названий и доз.

## Исправление зон нажатия A1 v2

Обратная связь пользователя выявила пропущенный критерий: 30px отметки, 4px между фильтрами и отсутствие свободного промежутка между строками. Размер текста и зоны управления ошибочно были уплотнены вместе. Правило добавлено в общие инструкции Codex и в проектные `AGENTS.md` / `DESIGN-RULES.md`. Новые зоны 48×48, между соседними строками/фильтрами 8px, между summary и отметкой 12px. Стрелка остаётся частью большой summary-зоны. Для проверки используется настоящий native checkbox, его состояние только в макете. На узком превью галереи фильтры переносятся, а не уменьшаются.

Минимальная сквозная проверка: опубликованный A1 на 390px → пробная отметка → раскрытие → независимые состояния, сохранён снимок `reports/a1-touch-canary-390.png`. Затем проверены 21 зона в каждом из шести телефонных/планшетных размеров, общий/личный фильтр и открытые инструкции; центр и оба края отметки, край раскрытия, отсутствие изменения соседней строки и колонок iPad. Фактические минимумы: 48×48px, промежуток 8px; измерения в `reports/design-study-check.json`. До исправления — `reports/a1-touch-before.json`. Скриншоты состояния покоя снимаются до touch-нажатий, чтобы не сохранять временную подсветку касания как вид кнопки. Все 51 тест и полный клинический canary прошли. Физические устройства не проверялись.
