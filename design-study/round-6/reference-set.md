# Медика — три контрастных цветовых направления

Пользователь отклонил зелёную тему и запросил ещё три контрастных темы разных цветов. Режим: replace для палитры и материала; содержание семейного экрана сохраняется. Два светлых и один тёмный вариант: белый/фиолетовый, светлый/оранжевый, тёмный бордовый/абрикос. Точные токены и промпты — `prompt-*.json`. Это новые изображения, рабочий интерфейс не изменяется.

Три из пяти записей — реальные native/platform поверхности. Кеш использован без новых веб-запросов. Предыдущие зелёные картинки не передаются генератору: прямой image-reference удерживал отвергнутые материал/композицию. Генерация с нуля по фиксированному содержанию; при ошибке группировки не делать широкую правку всех строк, исправлять только границу человека.

## Fingerprint и frame

RF1/RF2: умеренно плотная рабочая плоскость, разные веса заголовка/содержимого, минимум внешних контейнеров. RF3: первична задача, инструменты вторичны. RF4: негативная опора по контрасту и переизбытку цвета. RF5: расположение данных и принадлежность человеку не меняются при смене темы. Все три: один полноэкранный портрет, одинаковые четыре условные строки/имена/фазы/дозы/сроки/точки, без реальных медицинских данных. Entry → найти человека/препарат → отметка → состояние и курс; растровый макет отображает один шаг, не исполняет действие.

## Критерии

Доза и имя первичны, остаток курса читаем, числовой дроби прогресса нет. Фаза — простой пассивный текст, без переключателя. Каждому человеку принадлежат ровно две строки; «Обед» виден после них. Фиолетовая/оранжевая/бордовая гаммы должны отличаться сразу, не только оттенком активной кнопки. Никаких зелёных деталей. Текстовые пары токенов проверяются на контраст 4.5:1; это не проверка реальных пикселей или доступности будущего UI. Сначала один сквозной canary C1 (PNG → сохранённый файл/хеш → HTTP → крупное изображение/обновление → защита входом), затем остальные две генерации. `visualLock.status=unlocked`; пользователь выбирает финальную тему.
