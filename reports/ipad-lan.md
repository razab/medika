# Доступ с iPad — 8 ноября 2026

Установленная причина: прежний адрес medika.localhost относится к устройству, на котором его открывают. Дополнительно Caddy разрешал только loopback. Успешная проверка с Mac не подтверждала доступ с iPad.

Исправление: сохранить адрес Mac и добавить отдельный маршрут на стандартном HTTP-порту для Wi-Fi IP 192.168.0.38 и существующего Bonjour-имени macbook-air-5.local. Backend остаётся на loopback. Caddy допускает только loopback, текущую домашнюю подсеть 192.168.0.0/24 и IPv6 link-local fe80::/10 (Bonjour может выбрать IPv6). Приложение принимает только явно перечисленные Host и сохраняет проверку совпадения Origin.

Перед изменением рабочего Caddy выполнить proxy-canary с синтетической базой: страница и запись через LAN-IP, cookie/API, перезапуск, отклонение чужого Origin и запросов из запрещённой подсети. Конфигурацию и существующие маршруты сохранить. Реальные данные не использовать в браузерных тестах.

Не считать проверку с самого Mac проверкой физического iPad. Wi-Fi изоляция клиентов и сон Mac остаются внешними условиями. IP может измениться по DHCP; Bonjour-имя зависит от поддержки mDNS в сети. Отдельный DNS-сервер для этого решения не нужен. Доступ разрешён устройствам домашней подсети; отдельных аккаунтов и TLS в этой версии нет.

Во время проверки IPv6 установка остановилась до изменения рабочего файла: сравнение маршрутов через JSON.stringify без нормализации ошибочно считало другой порядок ключей изменением конфигурации. Проверка заменена сравнением с отсортированными ключами; минимальная read-only проверка подтвердила сохранение всех трёх прежних маршрутов. При ещё действующем IPv4-only правиле запрос с IPv6 link-local возвращал 403, поэтому Bonjour-путь дополнен fe80::/10 и проверяется отдельно.
