# Наблюдения по подходу

8 ноября 2026: полный вывод системного `/etc/hosts` оказался многомегабайтным из-за существующего списка блокировки рекламы. Чтение остановлено; файл не менялся. Вместо повторного вывода проверен только нужный hostname через `dns.lookup`: `medika.localhost → 127.0.0.1`. Для дальнейшего исследования конфигураций использовать ограниченный поиск и краткие проекции JSON, а не полные каталоги/реестры. Минимальная проверка нового способа прошла.

Новая модель, 8 ноября 2026: пользователь отверг разрастание главной в семейную доску, справочник и отдельные формы. Прежний UI сохранён в `archive/before-patient-first`; текущая главная ограничена выбором человека, его историей и единым вводом. Проверка на одном синтетическом приложении: изоляция пациентов, компактность 320–1470, закрытый контекст врача. Архивные UI-canary удалены из текущей версии, проверка перенесена в один актуальный сценарий.

На реальном локальном Whisper синтетическое «тридцать восемь и два» распозналось как `38-2`. Автоматически считать это обычным целым/диапазоном нельзя: допускается только узкий температурный формат NN-N с явным предупреждением перед подтверждением; диапазон 38–39 и лишние десятичные цифры оставляют поле незаполненным. Регрессии также проверяют диапазон доз с пробелами, отрицание приёма и несколько событий. Минимальная проверка прошла, затем повторён весь путь через опубликованный HTTPS с синтетическим микрофоном.

При чтении Apple Support получен HTTP 429. Запросы к этому источнику остановлены, повтора/обхода другим адресом не было. Инструкция установки сертификата подготовлена, но фактическая установка/разрешение микрофона на iPad не проверены. HTTPS и доверие к цепочке проверены локальным клиентом с явным корневым сертификатом; это не равнозначно проверке физического устройства.

Общий голосовой ввод: прежняя обязательная проверка каждого события и связь микрофона с выбранной вкладкой не соответствовали просьбе пользователя «просто голосом отправить общее событие». Голос отвязан от просмотра: имя только из фразы, известный однозначный факт сразу записывается, 15 секунд доступна отмена, неоднозначность открывает сверку. Относительное время закреплено до ASR, чтобы распознавание не сдвигало факт. Минимальный путь прошёл на синтетических данных: API → запись/повтор/отмена → перезапуск → копия/восстановление; затем реальный Whisper с микрофоном Chromium и автоотправкой по паузе.

Первый общий запуск unit-тестов выявил совпадение нового тестового порта с тестом температуры (EADDRINUSE). Чужой слушатель не останавливался: новый тест переведён на отдельный порт, проверены все объявления тестовых портов, затем полный совместный запуск: 22 PASS.

Переход из чата: скриншот пользователя показал JSON 403 вместо HTML. Регрессионный запрос с Sec-Fetch-Site: cross-site воспроизвёл проблему: blanket-проверка применялась ко всем маршрутам, включая публичную оболочку. Исправление разрешает только GET/HEAD страницы и публичного сертификата независимо от источника перехода. Проверки Host, API Origin/fetch-site, токен и запрет встраивания сохранены. Минимальный тест до изменения падал (403 вместо 200), после изменения проходит вместе с запретом чужого API/записи, даже с действительным токеном. Живой HTTPS-путь подтверждён; медицинских записей проверка не создавала.

Проверка браузерного перехода: новая синтетическая страница-ссылка не задавала charset. В полном canary браузер показывал русскую подпись в неверной кодировке, поэтому поиск ссылки по видимому имени не находил её; ожидание запроса тоже истекало, поскольку клик не происходил. Ограниченный вывод синтетической страницы установил причину. Исправлена кодировка fixture (text/html; charset=utf-8), ожидание заменено на пользовательский результат — клик ссылки и загрузка приложения, без незавершённого Promise. При перехвате allHeaders не содержал fetch-metadata, поэтому их наличие отдельно проверяется HTTP-регрессией и через опубликованный Caddy.

Пользователь указал на хрупкость цепочки «чистый ASR + ручные регулярные выражения» и выбрал уже оплаченную подписку Codex/Terra. Прекращено дальнейшее наращивание речевых regex: production-парсер заменён на структурированный ответ GPT-6.1 Terra с проверкой личности, количества и времени в обычном коде. Старый детерминированный разбор оставлен для unit-тестов и узкого определения явно названного пациента. Минимальный реальный запрос с синтетическим `38-2` прошёл, затем весь путь с Whisper, сохранением/отменой, копией и восстановлением — PASS. Terra по официальной спецификации принимает текст/изображения, поэтому качество первичного ASR не объявляется исправленным; аудио пока обрабатывает локальный Whisper. Системный CLI был 0.142.5, а Terra требует >=0.159: установлен изолированный 0.167.0, системный и глобальный config не менялись.

Сравнение речи вместо предположений: на шести одинаковых синтетических WAV текущий base→Terra дал 1/6 полностью верных автоматических записей, small→Terra — 2/6. Остальные запросили уточнение; неверных автоматических фактов в наборе не было. Ошибки затронули десятичную точку, «Дане»/«да не» и названия лекарств. Прекращено продвижение простой замены размера/названия модели как готового решения; production не переключён. Проверка качества одной чистой успешной фразой признана недостаточной. Перед следующей сменой движка сравнивать одинаковые записи с числами, именами, названиями и шумом; эталон не давать модели. Минимальный проход до полного набора проверил вход→ASR→Terra→поля→сохранённый JSON, возобновление и итоговый отчёт. Прямое localAudio→Sol low на двух тех же файлах завершилось только null-полями, поэтому путь не внедрён. Изначальный сбой app-server был ошибкой quoting MCP-ключей тестового запуска; исправленные ключи проверены handshake перед аудио-запросами.
