# Локальный домен без порта

Пользовательский адрес: http://medika.localhost. Существующий системный Caddy принимает порт 80 и передаёт запросы приложению на 127.0.0.1:4382. Порт приложения остаётся внутренним; hosts сопоставляет имя с IP и не задаёт порт. Имя уже разрешалось в loopback, поэтому hosts не изменялся.

Минимальный сквозной canary выполнен с настоящим Caddy и временной базой: открытие UI, создание синтетического профиля, относительные ресурсы, сессия/API, отклонение чужого Origin, перезапуск backend с восстановлением профиля. Результат — proxy-canary.json. На пользовательских данных тестовые операции записи не выполнялись.

При установке сохранены прежний Caddyfile и runtime-конфигурация в закрытом site/data/local-domain-backup. Перед загрузкой проверено соответствие файла работающему Caddy, кандидат прошёл caddy validate, оба существующих маршрута сравнены без изменений. Файл заменён атомарно; новый конфиг загружен через локальный admin API существующего Caddy. Новые OS-службы не создавались. Медицинский маршрут принимает только loopback-подключения.

Исправление подхода: прежний адрес содержал явный порт и не выполнял ожидание пользователя от локального домена. lsof без root не показал сокеты системного Caddy; вывод «прокси отсутствует» был бы ошибочен. После проверки launchctl/HTTP обнаружен уже работающий root-процесс, он переиспользован. Повторный bind порта 80 не выполнялся.

Проверка Host в тесте использует node:http: native fetch не передал подставленный Host как ожидалось. Защита приложения не ослаблялась ради теста. Unit/API-тесты подтвердили правильный Host без порта, доступ с совпадающим Origin, отказ чужому Origin и неизвестному Host.
