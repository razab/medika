# Медика на Hetzner

Публичный адрес — https://medika.ibhash.com. Cloudflare принимает HTTPS и передаёт запросы по выделенному туннелю `medika`. На VPS туннель обращается к Caddy на `127.0.0.1:4384`, а Caddy передаёт запросы в Node.js на `127.0.0.1:4382`. Оба порта доступны только на самом VPS.

## Cloudflare

- У `medika.ibhash.com` проксируемая CNAME-запись на `<UUID>.cfargotunnel.com`. Она относится к выделенному туннелю `medika`, который запускает `medika-tunnel.service`. HTTPS заканчивается на Cloudflare, а соединение до `cloudflared` шифрует туннель. Локальный шлюз перенаправляет HTTP на HTTPS.
- Конфигурация `/etc/medika/cloudflared.yml` начинается с `tunnel: <UUID>` и содержит правила из `cloudflared.yml` в этой папке. Учётные данные `/etc/medika/tunnel.json` принадлежат `root`, права 0600. Systemd передаёт их выделенному процессу через `LoadCredential`.
- Для изменения DNS использовать `cloudflared tunnel --config /etc/medika/cloudflared.yml route dns <UUID> medika.ibhash.com`. Сверить `tunnelID` в результате с выделенным UUID. При конфигурации без `--config` CLI может выбрать туннель из общего `/etc/cloudflared/config.yml`.
- Caddy передаёт IP посетителя из `CF-Connecting-IP` на локальном порту туннеля. Медика использует его для ограничения попыток входа. Приложение ставит `Cache-Control: no-store`. Правила кэша Cloudflare для этого поддомена должны учитывать этот заголовок.
- После изменений проверить `systemctl is-active medika medika-gateway medika-tunnel`, `curl -fsSI https://medika.ibhash.com/login` с `cf-ray` и `Cache-Control: no-store`, а также `401` у `/api/family` без сессии. При прямом обращении к IP VPS с именем Медики сайт не должен отвечать.

## Доступ

Каждый аккаунт даёт доступ к одному общему семейному журналу. Вход — по email и паролю. Регистрация требует одноразовый код, действительный 24 часа. Указанный email служит идентификатором аккаунта. Авторизацию выполняет только сервер. Он хранит хеши паролей с индивидуальной солью (scrypt) и хеши идентификаторов сессий. Браузер получает cookie `Secure`, `HttpOnly` и `SameSite=Lax`. Сессия длится до семи суток и истекает после суток бездействия. Записи требуют тот же origin и токен сессии. Проверки входа и регистрации ограничены по IP и идентификатору аккаунта.

Страница входа содержит одну форму с полями для менеджера паролей Chrome. Она отправляется обычным POST на `/login` и сохраняет проверку происхождения запроса. Для этой страницы действует `Referrer-Policy: same-origin`, чтобы Chrome сохранял заголовок Origin при отправке формы. Ошибка видна рядом с полем пароля.

Новый код выдаётся только через SSH. Выполнять от имени пользователя сервиса:

```sh
runuser -u medika -- env MEDIKA_DATA_DIR=/var/lib/medika/data \
  /opt/medika/runtime/bin/node /opt/medika/current/site/scripts/accounts.mjs invite
```

Команда `revoke EMAIL` в том же CLI отзывает аккаунт и все его сессии. Для восстановления доступа выдать свежий код после отзыва. Код приглашения передавать лично. Пароли, журналы, выписки, резервные копии и токены остаются вне Git.

### Вход по одноразовому коду

На устройстве с действующей сессией открыть **Аккаунт → Получить код для входа**. В новом браузере выбрать **Войти по одноразовому коду** и ввести этот код. Он действует 10 минут, срабатывает один раз и отзывается при выходе из исходной сессии. Новый код заменяет предыдущий. Сервер хранит хеши кодов и ограничивает число попыток.

Если действующей сессии нигде нет, администратор может выдать код существующему аккаунту через SSH. Передать его владельцу лично после проверки личности.

```sh
runuser -u medika -- env MEDIKA_DATA_DIR=/var/lib/medika/data \
  /opt/medika/runtime/bin/node /opt/medika/current/site/scripts/accounts.mjs login-code EMAIL
```

### Вход через Google

В Google Auth Platform создать OAuth-клиент типа **Web application** и добавить точный адрес перенаправления `https://medika.ibhash.com/auth/google/callback`. Настроить название и аудиторию на экране согласия. [Документация Google](https://developers.google.com/identity/openid-connect/openid-connect).

Клиентские данные устанавливаются на VPS в `/etc/medika/google.env` с владельцем `root` и правами 0600. Указать `MEDIKA_GOOGLE_CLIENT_ID` и `MEDIKA_GOOGLE_CLIENT_SECRET`, затем перезапустить `medika.service`. Кнопки появляются при настроенном клиенте. Сделать проверку с реальным аккаунтом Google после включения.

- Для существующего аккаунта Медики открыть **Аккаунт → Подключить Google** и подтвердить пароль от Медики.
- Для новой регистрации заполнить email и одноразовый код приглашения, затем выбрать **Регистрация через Google**.
- Медика запрашивает у Google только идентификатор аккаунта через область `openid` и привязывает его по `sub`. Email, введённый в форме, хранится в аккаунте Медики. Токены Google не сохраняются.

## Развёртывание и перенос

Перед переключением выпуска проверять синтаксис через `/opt/medika/runtime/bin/node --check <release>/site/server.mjs`. У SSH-сессии `node` отсутствует в PATH; фактический путь задан в `ExecStart` сервиса. При несовпадении сначала сверять `systemctl show medika -p ExecStart`, сохраняя текущий выпуск до успешной проверки.

- Код хранится под `/opt/medika/releases/`. Символическая ссылка `/opt/medika/current` указывает на активный выпуск. Шлюз использует `/etc/medika/Caddyfile`. Публичный режим требует `MEDIKA_PUBLIC_HOST`; локальный запуск на Mac использует прежний сетевой режим.
- Стойкое хранилище — `/var/lib/medika/data` с правами 0700. SQLite и файлы принадлежат системному пользователю `medika`. Оригиналы выписок, OCR-случаи, импорт упаковок, голосовая лаборатория и снимок дизайна входят в рабочую копию. Исторические локальные копии и сертификат Mac хранятся отдельно.
- Для переноса остановить запись на источнике и выполнить `node infra/hetzner/snapshot.mjs SOURCE DESTINATION`. Скрипт создаёт согласованную SQLite-копию, копирует рабочие файлы, проверяет ссылки в БД и SHA-256 оригиналов. Передать архив через SSH и сверить его SHA-256 до распаковки. Распаковать в приватный `/var/lib/medika/incoming.XXXXXX` и запустить `bash /opt/medika/current/infra/hetzner/activate-snapshot.sh <incoming>`. При ошибке запуска скрипт поднимает прежний журнал.
- Успешный запуск проверяется запросом на `/api/health` и браузерным входом. Без аккаунта `/api/family`, `/api/backup`, `/api/audit` и оригиналы возвращают 401. Новый выпуск проверять со свежим временным хранилищем, на синтетических данных.

## Распознавание

Linux использует FFmpeg и Tesseract с языками `rus+eng+ron` для изображений и OCR. Фото упаковки заполняет черновик карточки для сверки. Обработка аудио и создание фактов из голоса отключены в рабочем приложении. Тестовый стенд хранит свои записи отдельно. Подключение Codex к VPS отложено.

Проверять свободное место на VPS перед обновлением бинарных файлов или моделей.
